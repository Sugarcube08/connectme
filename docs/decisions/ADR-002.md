# ADR-002: Express MVC Architecture

## Status
Accepted

## Context
Connect Me requires a maintainable, decoupled backend where HTTP routing, request validation, business rules, persistence, and serialization are distinctly separated. Embedding API endpoints directly into Next.js Route Handlers would blur MVC boundaries and prevent clean reuse by the React Native client.

## Decision
Implement the REST API in Express.js with a strict MVC architecture:
1. **Router**: Maps paths to controllers and applies middleware.
2. **Middleware**: Authentication, request body validation, rate limiting, error catching.
3. **Controller**: Translates HTTP requests to service calls and formats responses.
4. **Service**: Contains authoritative business logic and use cases.
5. **Repository**: Executes persistence operations via Prisma ORM inside transactions.
6. **Serializer / DTO**: Maps internal records to safe public responses (excluding raw tokens, hashes, passwords).

## Consequences
- Business logic is independent of Express request/response objects.
- Easy to unit test services and integration test endpoints via Supertest.

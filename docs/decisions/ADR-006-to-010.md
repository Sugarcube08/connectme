# ADR-006: Web and Mobile Authentication

## Status
Accepted

## Context
Web dashboards running in browsers and mobile applications running on Android/iOS require distinct authentication transports while sharing the same identity and authorization rules.

## Decision
- **Web Dashboard**: Uses secure, HTTP-only session cookies with `SameSite=Lax` and signed JWTs. JavaScript cannot access the session token.
- **React Native App**: Uses short-lived Bearer tokens and refresh tokens stored in platform-backed secure storage (`expo-secure-store` / Keychain / Keystore).
- **Backend Authority**: Express auth middleware verifies active status and permissions identically regardless of whether the token arrives via cookie or `Authorization: Bearer <token>`.

# ADR-007: Single-Use Token Generation and Redemption

## Status
Accepted

## Context
Visiting cards distributed at Devcon have printed QR codes. If two attendees attempt to redeem the same code simultaneously, exactly one submission must succeed.

## Decision
- Generate 128-bit cryptographically secure random tokens (`randomBytes(16).toString("base64url")`).
- Store only the SHA-256 hash in MySQL (`tokenHash`).
- Redemption is executed within an explicit Prisma database transaction:
  1. Atomically update code from `ACTIVE` to `CONSUMED` where `tokenHash = $1 AND status = 'ACTIVE' AND (expiresAt IS NULL OR expiresAt > NOW())`.
  2. If 0 rows updated, throw appropriate typed error (`ALREADY_CONSUMED`, `TOKEN_EXPIRED`, `TOKEN_REVOKED`).
  3. Create `ContactSubmission` and optional `SubmissionImage` in the same transaction.
  4. Database unique constraint on `ContactSubmission.accessCodeId` provides secondary invariant guarantee.

# ADR-008: PostgreSQL Binary Image Storage

## Status
Accepted

## Context
Profile pictures must be stored privately without introducing third-party storage providers (S3, Cloudflare R2, Cloudinary).

## Decision
- Store image binaries in MySQL `LONGBLOB` using a separate one-to-one related table `SubmissionImage`.
- Normalizing and validating via `sharp` (max 2MB, formats JPEG, PNG, WebP converted to WebP).
- Ordinary contact list queries omit the `SubmissionImage` table, keeping list latency minimal.

# ADR-009: REST API Versioning and OpenAPI

## Status
Accepted

## Context
Both web and mobile clients require stable, documented contracts.

## Decision
- Prefix all API routes with `/api/v1/`.
- OpenAPI 3.1 specification at `docs/openapi.yaml`.
- Interactive Swagger UI served at `/api/docs`.

# ADR-010: Git Branching, Commits, and CI Requirements

## Status
Accepted

## Context
Disciplined engineering requires clean commit history, traceable pull requests, and automated verification.

## Decision
- Trunk-based branching: `main`, `feat/*`, `fix/*`, `refactor/*`, `chore/*`.
- Conventional Commits format: `feat(scope): ...`, `fix(scope): ...`.
- Automated checks: linting, formatting, type checking, and unit/integration testing on CI.

# ADR-005: Administrator Bootstrap and Account Recovery

## Status
Accepted

## Context
The application must create its first administrator without hardcoded credentials, seeded accounts, or an unauthenticated race to claim the administrator role.

## Decision
Use an explicit one-time provisioning flow:
1. **Provisioning:** An operator runs `pnpm db:bootstrap`. The CLI creates a pending placeholder administrator with a cryptographically random 256-bit token, stores only its SHA-256 hash, and prints the token to the operator's terminal. The token expires after 24 hours.
2. **Setup via web:** The operator opens `/setup`, enters the token manually, and chooses the administrator username, display name, and password. The token is not placed in a URL or environment variable.
3. **Permanent lockout:** The API atomically consumes the token, activates the admin, saves a bcrypt password hash, and closes setup. Re-running bootstrap does not replace a pending token; rotating a lost token requires an explicit operator command and is rejected after activation.

No `INITIAL_ADMIN_USERNAME`, `ADMIN_PASSWORD`, default account seed, or hardcoded credentials are used.

## Consequences
- The operator retains control over the first administrator identity.
- Tokens are single-use, expire, and are not logged into browser URL history.
- Setup cannot be reopened through ordinary API calls after initial activation.

# ADR-005: Administrator Bootstrap and Account Recovery

## Status
Accepted

## Context
Hardcoding default administrator credentials in source code or database seeds is an insecure anti-pattern. However, allowing arbitrary users to claim an administrator username creates a dangerous race-to-claim vulnerability.

## Decision
Implement a controlled three-phase First-Admin Bootstrap flow:
1. **Provisioning**: During deployment, set `INITIAL_ADMIN_USERNAME` (e.g. `harsh`). The provisioning CLI or deployment runner executes `pnpm db:bootstrap`, creating a pending administrator record with a cryptographically secure 128-bit one-time bootstrap token (`BOOTSTRAP_TOKEN`).
2. **Setup via Web**: The administrator navigates to `/setup?token=<BOOTSTRAP_TOKEN>`, where they set their password, display name, and optional profile picture.
3. **Permanent Lockout**: Upon completion, the password hash is saved (bcrypt, salt 12), the admin record is marked `isActive = true, isBootstrapPending = false`, the bootstrap token is permanently revoked, and the `/setup` endpoint is closed to all further initialization.

## Consequences
- Zero hardcoded passwords in Git, seeds, or Docker images.
- Unauthenticated visitors cannot claim the admin account without the physical/deployment-delivered one-time token.
